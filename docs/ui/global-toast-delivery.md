# 全局 Toast 投递

桌面窗口被遮挡或最小化、Web 页面在后台时，浏览器可能不执行动画帧回调。提示的挂载和可见态不能依赖动画帧；动画只负责装饰，不控制提示是否进入 DOM。

```text
toast / updateToast / dismissToast → 首次挂载前的待投递项
                               → 容器挂载时按顺序接收 → ToastContainer 管理已挂载项
```

- 首次发出提示只创建一个宿主。挂载前更新待投递项，关闭直接删除该项；挂载时按加入顺序投递，之后由容器处理新增、更新和关闭。
- 保留现有位置、去重和锚定行为。提示挂载即进入显示态，进入动画由 CSS 管理并尊重减少动态效果偏好；保留退出过渡和自动关闭。
- `durationMs=0` 的提示持续显示，更新为正持续时间后开始自动关闭。

## 验收

1. 在 Chromium / Electron 页面拦住 `requestAnimationFrame` 回调。冷启动时连续发三条提示，其中一条立即更新、一条立即关闭；不解冻动画帧，验证一个宿主、更新后的文本和剩余提示的顺序，已关闭的提示不得进入 DOM。
2. 容器挂载后，不解冻动画帧；发出相同去重键的新提示并立即更新，验证新提示替换旧提示，且从持续状态更新为短定时后可以自动关闭。
3. 恢复动画帧，检查右上角提示和减少动态效果模式；提示的关闭动作及退出方向保持原行为。
