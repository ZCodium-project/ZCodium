# ZCodium v1.17.0

## 本次更新

这是 [#79](https://github.com/ZCodium-project/ZCodium/issues/79) 的**功能发行**：补齐本地同项目多目录及一组不依赖官方账号的工作台能力，并修复集成中实测发现的恢复、导航和沙箱接线问题。它不是 v1.16.3 的重发；需要安装本次发行的 v1.17.0 才能获得这些变化，已有公开 v1.16.3 不因此自动包含本轮功能。

对齐参考为官方开源 `zai-org/ZCode@3c5b227649371507ddc4eb46ac5133afe6db1cab`（package 版本 3.16.2，并非同名官方 tag）。这里的“对齐”不表示恢复官方云服务，也不表示所有上游能力都已完整实测。

### 1. 一个本地项目，多个目录

- 项目编辑器支持系统一次多选、继续添加、移除、去重、改名及设置主要目录；保存和重启后保留项目 roots 与主要目录。
- 项目内新任务从主要目录启动，保留明确的项目归属。**修改主要目录或移除 root 不会改写旧任务 cwd**；新任务使用新的主要目录。
- 文件提及覆盖项目的所有 roots；同名文件显示来源，非当前 cwd 的文件使用正确的绝对引用，不再只搜当前目录。
- 当前附加目录贯穿创建、显式恢复与 V4 冷恢复，参与 Skills、Commands、Subagents 的发现和可读写范围；同名能力保留来源限定。已有运行实例不会因订阅或重连被重新配置。
- 不扩大可执行配置的信任范围：AGENTS、settings、MCP、hooks、plugins、memory、permissions 仍沿会话绑定目录链加载，不因为项目多目录而全部合并执行。

### 2. 草稿、恢复与迟到事件修复

- **同 cwd 的不同项目草稿隔离**：按客户端、Host 和项目上下文保存未发送内容，切换或重启后不再因路径相同而串草稿。
- **旧任务冷恢复**：保留正文、原 cwd 和原归属；重新创建运行实例时补齐当前项目附加目录，不再退回仅 cwd 的能力范围。
- **插件成功事件接线**：成功 MCP 工具结果从权威投影提交后通知 UI，让后台页面能获得实际工具结果；保留结果校验、去重、会话与代次隔离，不把失败结果当成功广播。
- **远端 late-navigation 修复**：旧 attachment 的补充读取结束后不再重复初始化草稿或抢回任务。草稿在唯一激活边界一次性交接，保留正文、模型/模式、附件和项目意图；用户后选任务、新草稿或导航换代使旧结果失效。
- **正式 Main 沙箱启动修复**：补齐沙箱 scheme、完整 host 安装与窗口 Host 登记，解决卡片存在但 guest 因缺少 owner IPC 无法启动的问题；不是仅让可视化卡片“显示出来”。

### 3. 工作台与个人来源能力

- **GenUI**：正式消息流展示本地交互式可视化，支持展开/收起及确认后向原会话续写；复用同一 guest 和页面状态，失效实例不能发送。Web/手机不因此获得本地沙箱。
- **完整视图（fullView）**：侧面板可进入完整视图并切换对话 tab、浮动对话；复用唯一会话 Pane，保留未发送编辑和附件，不移除本仓已有分屏能力。
- **自有 Source 管理**：接入设备列表、线路编辑、连接进度、升级及迁移日志入口，沿用已有 Host owner 与离线资源链路；后台连接完成不自动抢导航。入口和确定性回归已接通，不等于真实 SSH 升级/force 全流程已验收。
- **个人来源插件**：逐项操作 busy 状态，操作 A 不再无条件锁住 B；成功变更刷新对应范围的入口。工具页面可在隐藏/切页时初始化或保留执行，手动打开的文档使用独立实例，关闭一个不影响另一份。
- **消息呈现**：clipboard-text/topic-history 文本来源支持预览；Bot 合批按原发送人和原消息拆分呈现，保留正文、附件与来源对应关系，不把局部编辑当作整批替换。
- **所有 roots 配置目录与工作流归属**：插件、MCP、Skills、Commands、Hooks、Subagents 的目录候选来自 Host 项目目录，不限于打开的 tab。定时/闲时自动化、保存工作流及再次运行携带 projectId/hostId，不用 cwd 猜归属；浏览候选不启动 Agent，远端断连不回落写本机。

### 4. 继续保留审计版边界

- 保留 ZCodium 品牌、独立版本、MIT 第一方许可、上游许可声明及 `.zcodium` 数据根。
- 遥测、监控、仓库快照打包与上传的剥离继续保留；不为修测试或接 UI 恢复这些模块。
- 使用个人 API Key 或自定义 Provider，不依赖官方账号。**官方账号、购买和分享入口已下线，不能通过开关恢复**；仅插件市场与客户端远端配置仍可选择开启，默认关闭。
- 本轮继承 [#68](https://github.com/ZCodium-project/ZCodium/issues/68) 的 SSH 资源、离线导入、canonical bind 与取消边界，不将其重新包装为本次新增。
- 本轮也继承已合并的 `61eef508`（[#76](https://github.com/ZCodium-project/ZCodium/issues/76)，经 PR #78 合并）：双架构更新清单由唯一 job 汇总并验证真实发布资产。它是本轮起点已具备的元数据修复，**不是 #79 新增修复**；构建、验证与成功后才公开的发布门禁保持不变。

## 已知限制与验证范围

### 明确未恢复的能力

- **远程项目仍只有一个固定 root**，不提供远程任意目录或多 root 编辑；本地多目录不等于远程多目录。
- **官方公网手机配对入口未恢复**。已有配对 bridge 的项目链路有 adapter/Host 准入回归，但不能据此宣称公网手机远控已贯通；自有授权与配对入口仍需单独设计。
- Computer Use 仍为不可用占位；本轮未恢复官方分享、账号、购买或公网 relay 依赖。

- CLI 类型检查 30/30；目录、冷恢复及后台工具事件专项通过。CLI 扩展批次 **273 通过、41 失败**，41 个失败标识与只读 HEAD 基线一致，无新增失败，不能称为 CLI 全部通过，也没有恢复已移除模块来消除基线失败。

- 真实发送使用 loopback 合成模型 fixture，只证明请求范围、UI 和运行链路，**不代表模型能力或回答质量提升**。窄屏检查不等于实体手机远控验证。
- **尚未完整实测**：真实 SSH 管理/升级/force/身份变更、插件长期后台/最小化编辑、多文档长期独立编辑、Bot 多人真实入口、Windows/Linux GUI；确定性测试不替代这些验收。

- 第三方通知与输入新鲜度已核对；许可台账仍有 15 项既有材料待审项。基础检查不等于严格材料完整性通过，详见 [第三方材料说明](https://github.com/ZCodium-project/ZCodium/blob/v1.17.0/third-party/README.md)。

## 下载与安装

从本次 Release 的 Assets 下载对应文件，并使用 `sha256.txt` 校验。安装包**没有 ZCode 官方签名**，仅从本仓库可信发行来源获取，不应把“未签名”误写成已获官方认证。

| 平台                | 文件                                    |
| ------------------- | --------------------------------------- |
| macOS Apple Silicon | `ZCodium-1.17.0-mac-arm64.dmg` / `.zip` |
| macOS Intel         | `ZCodium-1.17.0-mac-x64.dmg` / `.zip`   |
| Windows x64         | `ZCodium-1.17.0-win-x64.exe`            |
| Linux x64           | `ZCodium-1.17.0-linux-x86_64.AppImage`  |
| Linux arm64         | `ZCodium-1.17.0-linux-arm64.AppImage`   |
| CLI（Node.js 24）   | `zcodium-1.17.0.tar.gz`                 |

- macOS：打开 DMG 并拖入“应用程序”；首次启动可能被 Gatekeeper 拦截，核对来源与校验和后，按系统“隐私与安全性”提示允许打开。
- Windows：运行 EXE；若 SmartScreen 提示，核对来源与校验和后再决定是否“更多信息 → 仍要运行”。
- Linux：给对应 AppImage 执行权限后运行，例如 `chmod +x ZCodium-1.17.0-linux-x86_64.AppImage`。
- CLI：解压 `zcodium-1.17.0.tar.gz`，进入 `zcodium` 目录运行 `./install.sh`，再执行 `zcode --help`；也可运行 `node bin/zcode.mjs --help`。
- 更新清单为 `latest*.yml` / `latest.json`；产物、校验和和最终桌面更新清单仍须通过原有 CI 门禁后才公开。

## English summary

- **Feature release for #79, not a replacement of v1.16.3.** Local projects support multiple folders, a primary folder, all-root file mentions and additional-directory discovery for skills, commands and subagents. Existing sessions keep their original cwd and configuration trust boundary.
- Isolate project drafts even with the same cwd; preserve additional directories on cold resume; connect successful plugin events; reject stale remote navigation; wire the complete Main sandbox startup so GenUI guests actually run.
- Add interactive GenUI follow-up, full-view/floating conversation presentation, self-owned Source management, per-plugin operations/background pages/independent documents, text previews and sender-aware Bot batches, all-root configuration targets and project-aware automation/workflows.
- Keep ZCodium branding, `.zcodium`, telemetry/upload removal and personal providers. Official account, purchase and sharing features remain removed; only marketplace/client-config integrations are optional and off by default. #68 remote fixes and the already-merged #76 metadata fix (`61eef508`) are inherited, not newly claimed #79 work.
- Remote projects remain single-root; public mobile pairing is not restored and self-owned authorization needs a separate design. Real SSH upgrade/force, long-running background/multi-document editing, multi-user Bots and Windows/Linux GUI are not fully exercised.
- **Validation is scoped:** 84 focused files / 622 tests passed, not full UT; the expanded CLI batch has 273 passes and the same 41 baseline failures. macOS arm64 directory-app tests include real GenUI guest interaction and original-session follow-up. Synthetic model fixtures do not demonstrate improved model capability. A successful `.app` directory build is not a verified DMG; installers have no official ZCode signature.
